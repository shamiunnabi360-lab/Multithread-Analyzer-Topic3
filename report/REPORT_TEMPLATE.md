## 2. Design (about 1.5 pages)
- Input: directory of files, memory-mapped with `mmap`; a **task** is a byte range of one file.
- Line alignment rule: a range owns every line that *starts* inside it, so no line is split or counted twice
  (code: `run_task`). Tested with chunk sizes of 1, 3, 7, 16, 25 bytes.
- Sequential baseline: `-m seq`.
- Race demo (`-m race`): `volatile` load, add, store on a shared counter with no lock. Explain the lost-update
  interleaving: T1 reads 5, T2 reads 5, both write 6 (expected 7).
- Fix 1 (`-m mutex`): lock around each increment. Correct but a lock/unlock per word.
- Fix 2 (`-m local`): private counters per thread, merged once under a mutex. Lock ownership: `gmtx` is held only
  for the merge. Justify: no sharing during the hot loop, so no contention.
- Distribution: static round-robin vs dynamic atomic queue (`__atomic_fetch_add`) vs dynamic + chunks (challenge).
